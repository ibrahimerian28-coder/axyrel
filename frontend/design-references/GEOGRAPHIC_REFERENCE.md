# Geographic and telephone reference snapshot

Snapshot: 2026-10-05. Frontend geography.json is generated reference data, not a new address framework or a claim of universal locality coverage.

- Countries/subdivision codes: pycountry 26.2.16, derived from Debian iso-codes (ISO 3166). Upstream source and license: https://github.com/pycountry/pycountry and https://pypi.org/project/pycountry/26.2.16/ . LGPL 2.1 text accompanies this snapshot in geography-LGPL-2.1.txt. Package data retains its upstream copyright/license; the generation script is provided in this repository.
- Calling codes and server phone validation: phonenumberslite 9.0.40 (libphonenumber metadata). https://github.com/daviddrysdale/python-phonenumbers and https://pypi.org/project/phonenumberslite/9.0.40/ . Apache 2.0 package. New phone records are validated and formatted E.164 server-side, without guessing unresolved legacy numbers.
- Egypt governorate names and locality suggestions: GeoNames https://www.geonames.org/ , daily download https://download.geonames.org/export/dump/EG.zip and admin1CodesASCII.txt . GeoNames data is CC BY 4.0, https://creativecommons.org/licenses/by/4.0/ . Attribution: GeoNames; changes: populated-place names are grouped by governorate and deduplicated. 27 governorates map to reviewed ISO codes; 11,473 locality suggestions are included. Input hashes, package versions and snapshot date are recorded inside geography.json.

To rebuild after an explicit reference-data review, install pinned requirements, download those two GeoNames files into a local directory, then run `python tools/build_geographic_reference.py path/to/admin1CodesASCII.txt path/to/EG.zip`. Inspect mapping, updated package versions, source hashes/date and the generated diff before committing. No browser request to a third-party geographic service is needed.

Selecting a different country clears state/locality; selecting a different governorate clears locality. Egypt suggestions depend on that governorate. Suggestions are not exhaustive official postal/district validation; free-text actual locality is allowed. Other countries use ISO subdivisions where available and free-text locality. Countries lacking subdivision entries permit omitting that optional field. No locations or hierarchy are fabricated. Address and map URL belong to the Asset; the Customer's legacy location fields remain unchanged and are never automatically assigned to one of multiple Assets.
